# ADR 0006 — Account-first usage exploration and quota-cycle history

Status: **ACCEPTED — user-approved direction; implementation and acceptance pending**  
Date: 2026-09-07  
Scope: desktop information architecture, query scope, token presentation and quota history.  
Delivery: existing Rust / React / native application; no replacement dashboard runtime.

## 1. 产品目标

以 Codex 的导航习惯为基础，让用户连续完成：

**选择账号和时间 → 查看使用趋势 → 找出项目或聊天 → 查看实际模型与 Token 组成 → 复盘额度刷新周期。**

保留总览和工作区；账号入口固定在左下角，支持全部账号与历史账号。
不复制 Codex 的聊天编辑器，不在每个项目页面重复展示全局账号诊断。
本方案不实现计费，不将 Token 数等同于产出质量、开发效率或固定额度。

## 3. 信息架构与账号交互

### 3.1 左侧

- 总览：全部工作使用情况、趋势、项目排名。
- 工作区：保留文件夹列表与当前范围 Token 数；独立聊天为同级入口。
- 聊天搜索：总览与项目内部提供，不把所有子代理展开在侧栏。
- 左下角固定账号入口；服务状态缩为状态点，诊断进入二级面板。

账号弹层包括：全部账号、每个已记录账号、套餐标签、当前登录标记、最近观测时间、账号与额度、设置。
未知账号归属作为数据分组保留，不伪造一个已识别账号；也不能把工作区身份数直接当作人的账号数。

**当前登录账号与查看账号是两个独立状态。**
左下角显示“查看：全部账号”或选定别名，弹层单独标记“Codex 当前登录”。
选择账号只过滤看板，不调用登录、登出或账号切换接口；观测到登录变化时更新登录标记，默认不抢走用户正在查看的范围。
所有账号都有最后观测时间；不能刷新未登录账号时保留上次数据和时间，不显示成实时。
默认使用别名和脱敏标识，不为显示头像而读取凭据。

### 3.2 右侧页面责任

| 页面 | 必须回答的问题 | 不应该出现 |
| --- | --- | --- |
| 总览 | 所选账号在此时间用了多少；主要模型、项目、聊天及变化 | 把官方 Total 与本机缓存比例配成一个指标 |
| 项目 | 此项目消耗、模型构成、聊天排名、时间趋势 | 全局其他项目的排行或全局补齐说明占据主画面 |
| 独立聊天列表 | 哪些无项目聊天消耗最多 | 为无项目聊天硬配项目；显示其他项目排名 |
| 聊天详情 | 本身与子代理分别用了多少；每个模型、轮次、请求何时消耗 | 用聊天创建时的模型代替实际调用模型 |
| 账号与额度 | 单账号官方统计、不同额度池、历次刷新和同区间 Token | 所有账号百分比求和；把账号活动重复算入多个池 |

总览保留“账号比较”入口；模型分析用总览标签及详情面板，不必须增加一级导航。

## 4. 全局范围与数据来源

一次提交的范围包含账号集合、时间模式、起止、时区、模型、页面实体、own/tree、来源和快照版本。
顶栏只保留时间、模型、刷新及更多选项；账号移到左下角后，标题仍显示当前账号范围。
导航进入项目或聊天时保留账号、时间和模型；返回保留搜索、滚动和分页位置。
筛选返回前保留旧范围与旧数据；新范围结果原子替换，旧请求不得覆盖新请求。

两套账本分开呈现：

1. **工作用量（本机记录）**：默认总览、工作区、聊天、模型、Token 组成全部基于这一来源，能在同范围内逐级对账。
2. **账号用量（官方记录）**：账号页及总览的独立对照入口。按实际提供的字段与设备/时间覆盖显示；只有 Total 就只显示 Total。

不将官方差额按本机项目比例摊分；不拿本机缓存比例解释官方总数。
全部账号缺少档案时显示“已同步账号合计 / 待同步账号数”，不悄悄改成另一来源。
精确是对于已定义范围和证据的精确，不保证缺失历史可恢复。
少量状态放在数字旁，详细缺口进入可展开诊断；告警文案不替代根因修复。

## 5. Token 单位及组成规范

统一 **M tokens = 1,000,000 tokens**；中文、英文、坐标轴、排行、菜单栏使用相同单位。
例如 12,345,678 显示 `12.35 M`，悬停/键盘聚焦/复制提供整数。
小值增加有效小数位，低于显示精度显示 `<0.001 M`，不将非零四舍五入成零。
零显示 `0 M`；未知显示 `—`；导出同时保留原始整数与单位，不在存储层缩放。

模型组件默认字段：模型、总量、输入（非缓存）、缓存读取、缓存写入、输出、请求数；缓存命中率可展开。
输入总量是包含缓存的父指标，不能与缓存再相加。

- 原始输入总量记为 I，缓存读取 R，明确记录的写入 W，输出 O。
- 经来源语义验证写入属于输入子集时：非缓存输入 U = I − R − W；Total = U + R + W + O。
- 写入字段缺失时，不推测 W=0：显示“输入剩余（未细分）= I−R”、缓存读取、输出，写入为 `—`。
- 部分记录能拆分时，显示已观测写入与未细分输入，并注明字段覆盖；不能以“非缓存输入”隐藏未知写入。
- 命中率为同一范围已知读取量 / 对应输入总量；不得以 Total 作分母，缺少输入明细则不可计算。
- Reasoning 作为输出子项，不加入总量第二次。

新增独立 Token 格式化入口；保留请求数、会话数、时间与百分比各自格式。
不静默改变已有 DTO 的 uncached 语义；先核验并更新契约及兼容字段，再迁移显示标签。

## 6. 页面与图表设计

### 6.1 总览

第一屏：紧凑范围栏 → 所选期间 Token 与组成摘要 → 使用趋势 → 项目/模型/聊天排名标签。
账号官方对照作为独立入口，不用另一套超大总量盖住可下钻的工作用量。
排名默认当前范围；支持本周、本月、至今快捷范围，改变范围时卡片、图、排行一起更新。
如用户固定侧栏范围，必须显示“已固定”及实际日期，并提供恢复同步，不能出现隐性不同口径。

### 6.2 项目与聊天

项目页复用范围栏、趋势和模型表；聊天列表列出 Token、模型混合、子代理数、最近活动。
模型表默认显示全部可用模型（长表分页），排行预览提供“其他合计 / 查看全部”，不截断分母。
点击模型会应用明确筛选并显示可撤销的标签。
聊天页用“本聊天 / 含子代理”切换；模型表、曲线、组成、轮次表同时更新。
主聊天自身 + 后代各自用量 = 树总量；不累加父节点已含后代的树总量。
单个子代理支持继续下钻；独立聊天与项目聊天共用同一明细能力。
轮次没有完整请求明细时显示不可用，不平均分摊会话总量到每轮。

### 6.3 图表约定

| 问题 | 展示 | 交互与边界 |
| --- | --- | --- |
| 每天/每周/每月使用如何变化 | 分桶折线；少数离散桶使用柱图 | 点选/框选定位日期和贡献聊天，保持完整日历轴 |
| Token 组成如何变化 | 四类堆叠柱；缺失写入保留未细分输入 | 与 Total 守恒，未知区间留缺口，不插值为零 |
| 哪个项目消耗最多 | 横向排名条 + 全量表 | 默认降序、明确分母，包含独立聊天和未匹配分组 |
| 哪个模型在哪段时间活跃 | 模型分色趋势或分面图 | 默认少量主要模型，其余合并且可展开；颜色跨页面稳定 |
| 一次额度刷新后发生了什么 | 额度剩余阶梯线 + 同时间轴 Token 柱图 | 上下分图，不用百分比与 Token 共用数轴；标出观测缺口及重置 |

日期范围与趋势粒度独立：今日默认小时、本周/本月默认日、本年默认月；用户可选日/周/月。
日界按选定时区，半开区间 [start,end)；自然周按明确周起点，跨月照实显示日期。
累计是单独模式，不把每周柱图变成累计曲线。
本期未结束和来源未覆盖分开标示；环比只比较同长度、可比覆盖，不对零基线显示无限增长。
稀疏数据不平滑；示例图只使用合成数据。本轮不生成伪造真实曲线。

## 7. 额度刷新周期账本

### 7.1 身份和分段

周期主键概念为：账号 × workspace 身份范围 × limitId × 窗口角色 × 周期序号。
每条观测保存观测时间、官方截止时间、窗口长度、已用百分比、来源和可验证状态；缺失字段保持空。
自然到期、同截止时间提前恢复、截止时间变化、离线后首见、不确定下降应分别建模。
预计周期起点（截止减窗口长度）与实际首次观测、确认的重置时刻是不同字段。
仅看到截止时间变化不能证明新额度到账；异常下降先记候选事件，确认后分段，证据不足保留待确认。
本机短暂离线不能补画“100%”；实际重置若只能定位到两次观测之间，就保存边界区间。
用户填写 bank reset/其他重置备注是用户声明；只有独立可验证回执才能升级为已验证原因。
本功能只观察和记录，不自动兑换重置、不操纵额度。

### 7.2 用户可看到什么

- 单账号：当前各池剩余%、截止时间、最新观测；全部历次周期可翻页。
- 每个周期：起止/持续时间、初末额度、已观察下降与恢复、期间账号 Token 和四桶、主要模型与项目。
- 比较完整周期的实际消耗量；提前重置周期单独标识，不与完整耗尽周期直接当作相同容量样本。
- 全部账号：并列账号卡和周期列表。各自“当前周期”不同步，只能称“各账号当前周期汇总”，不冒充统一日历范围。

同一请求可能同时受到短窗和周窗限制。Token 事实只计一次，不能把多个窗口的活动合计相加。
只有明确池归属证据才能标作“该池 Token”；否则标作“同时间账号 Token”，不能按模型名称猜池归属。
周期边界必须使用精确时间证据，无法精确分桶时说明缺口，不按小时平均切分。

### 7.3 “给了多少额度”的可回答范围

明确分开三件事：官方报告的百分比状态、观察到的恢复幅度、周期中实际记录的 Token。
完整观测可以统计一个周期实际用了多少、何时恢复；不完整观测只能报告已观测部分。
比例点变化是观测值，不自动代表可跨套餐/模型/规则加总的绝对容量。
未来可展示同账号/同池/同配置完整周期的经验范围和样本数，但不将一次 Token/百分比比值外推为固定 100% Token 配额。
本期不实现价格与费用估计，也不承诺未暴露的官方绝对 Token 上限。

## 8. 视觉、性能与模块边界

系统字体，正文约 14px、辅助文字不低于 12px、主数值 24–28px；保持现有 Cmd+/−/0。
左侧约 224–248px，可折叠；右侧有一个主滚动容器，长表在明确区域横向滚动，禁止滚轮陷阱。
1280×800 默认缩放优先显示核心指标、主图和排行入口；窄窗改单列，不以持续缩小字体硬塞一屏。
账号菜单不能被底部裁切。浅色/深色、中英文、键盘、触控板、焦点提示与减少动态效果一起验收。
刷新按钮固定尺寸，后台更新不反复更换整页内容；失败保留 last-good 视图并显示过期状态。

模块职责：

- 采集与来源身份：只增量处理新证据，不随页面加载重新全量扫描。
- 统计查询：统一 Scope 和快照，负责时间桶、过滤、分母与对账。
- 账号目录：稳定身份和登录观测；与所查看范围分离。
- 额度周期：快照、分段、重置证据、历史分页；不得写入 Token 主账。
- Token 展示：独立单位与组成格式；纯函数测试。
- 通用视图：ScopeBar、AccountSwitcher、UsageTrend、ModelUsageTable、Composition、ConversationList。
- 页面编排：总览/项目/聊天/账号只决定范围和布局，不各自重算统计。

沿用模块治理和版本化 DTO；新增字段优先可选兼容，数据库迁移先影子验证和回执。
不因重新设计删除原始账本、重建真实历史或重新归属未知账号。

## 9. 实施顺序与验收

1. **P0 数据契约**：统一范围/版本；核验四桶与未知写入语义；修复来源重叠策略并完成受控迁移。设计展示可并行，精确性宣称不能提前。
2. **P1 账号与 M 单位**：左下角账号选择、查看/登录分离、全局 Token formatter、受保护偏好存储。
3. **P1 主使用路径**：总览/项目/聊天共用模型表、日期趋势、排名和下钻；单元与组件验收。
4. **P2 完整周期账本**：历史分页、同截止重置、池隔离、离线缺口、周期/项目/模型查询。
5. **P2 原生与跨平台验证**：响应式、中英文、键盘、重启/刷新、长会话及高频更新；记录实际运行平台，源码构建不等于安装包验收。

必须自动化的检查：

- 同来源/范围/快照：全部账号 = 已识别账号之和 + 未归属账号；不得低于任一子集。
- 工作总量 = 项目 + 独立聊天 + 未匹配记录；模型含未知桶之和守恒；分页不改变分母。
- 总图分桶之和、表格、导出与总数相等；只有区间包含关系成立时才能断言周不大于月。
- 四桶完全可拆时守恒；写入未知不变零；缓存比例只能用对应输入；Reasoning 不重复加。
- 同账号换模型、同聊天换账号、子代理重放、重新启动、迟到事件不会重复或改贴标签。
- 两账号同 resetAt 不合并；同账号不同池隔离；重复快照不生新周期；同 resetAt 恢复可记录；离线不补造边界。
- Token 单位不改变原始值；零/小值/未知/大值双语显示；仅 Token 用 M。
- 切换账号/时间后快速导航不出旧结果；Today 空数据、无完整写入、存储不可用不白屏。
- 560/900/1280px 宽度与 100%/125%/150% 缩放可达最终表格列、账号菜单和最后会话。

用户任务验收：找出选定账号上月最耗 Token 的聊天；解释其模型和输入/缓存/输出；定位某天峰值；比较两次完整额度周期。必须能从界面自行完成，不依赖开发者口头解释。

## 10. 决策边界

拒绝：把不同来源静默合并为一个大数、官方差额按项目分摊、账号过滤触发登录、百分比当 Token 上限、只改字体不改范围、把所有表强塞首屏。
兼容影响：需版本化周期 DTO 与可能的周期持久化；保留已有请求事实、身份和原始数值；写入语义变更须先更新契约。
隐私：公开测试、文档与截图全部合成；账号菜单与导出支持脱敏；不读取或请求凭据。
