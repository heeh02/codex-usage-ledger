# Architecture decision records

Use an ADR for a lasting change to accounting semantics, schema compatibility,
identity, security/privacy boundaries, supported platforms, API compatibility,
or dependency direction.

Name records `NNNN-short-title.md` and include:

1. status and date;
2. context and evidence;
3. decision;
4. rejected alternatives;
5. compatibility, migration, privacy, and testing consequences.

An ADR explains why a contract changes. It does not replace the contract,
implementation, migration, or verification receipt.
